## REMAINING — the ONLY gate before Tor can ship: C3 device/waydroid validation
Everything verifiable without a device is done. C3 (checklist in `docs/TOR-ONION.md`)
needs the Tor network + a device/waydroid:
1. Pair on LAN → confirm `focus_lock_onion_addr` populated + returned in `/api/pair`; Lion stored the `.onion` candidate.
2. Control port: `ADD_ONION ED25519-V3` + `ClientAuthV3=` accepted (assert ServiceID == derived .onion); Lion `ONION_CLIENT_AUTH_ADD x25519:` accepted.
3. **`foregroundServiceType` — top risk:** the AAR declares NONE; if `TorService` calls `startForeground` under API 34+ it crash-loops. Add the matching type to both manifests if so.
4. Disable LAN+relay → ntfy wake → Collar Tor bootstrap → Lion connects to `bunny.onion`; lock/unlock round-trips (~30s–2min cold budget); warm toggle (`focus_lock_tor_warm`) = instant.
5. Client-auth: a 2nd controller without Lion's x25519 key cannot connect.
6. Relay auto-fallback intact when Tor can't bootstrap (no silent failure).

**Keep `FOCUSLOCK_TOR_AAR` UNSET in production until C3 passes.** The additive design
makes that safe (off-build is Tor-free).
