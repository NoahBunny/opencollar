## 0. Prerequisites (get this order right or the service crash-loops)

Target: Samsung **SM-S908**, adb serial **`R5CT339K1ZL`**, Android 16 / API 36,
over USB. Details and the reasoning behind each step live in the
`on-device-adb-qa` and `bunny-phone-provisioned` notes.

- [ ] Slave 81 needs a **fresh install** to pick up the ShadeGuardService +
      `selfNodeId()` changes. Item F/D-14 additionally wants a **factory-fresh
      join** to be meaningful — do the phantom-node check before re-pairing.
- [ ] `pm grant com.focuslock android.permission.WRITE_SECURE_SETTINGS` **before**
      starting the service — `initMesh()` writes `Settings.Global` unguarded and
      dies on onCreate without it.
- [ ] `pm grant com.bunnytasker android.permission.WRITE_SECURE_SETTINGS` too —
      Bunny Tasker's in-app "Join Mesh" writes the join config to `Settings.Global`.
      Without it the join POST succeeds server-side but the local write fails
      ("Join failed — Permission denial"), leaving a half-joined state. Verified
      on device 2026-08-07; `recage_focuslock()` now grants this (was collar-only).
- [ ] Recage via `installers/re-enslave-phones.sh` (or `recage_focuslock()` in
      `installers/re-enslave-lib.sh` by hand): 6 perms, `dpm set-active-admin`
      for **both** `com.focuslock/.AdminReceiver` and
      `com.bunnytasker/.AdminReceiver`, `focus_lock_consented=1`, HOME role →
      `com.focuslock`, then
      `am start-foreground-service -n com.focuslock/.ControlService`.
- [ ] `adb -s R5CT339K1ZL forward tcp:8432 tcp:8432` for host-side pokes.
- [ ] **ShadeGuard must be enabled by hand** — `settings put secure
      enabled_accessibility_services` silently reverts on Android 13+ for
      sideloaded apps. Collar App info → ⋮ → *Allow restricted settings*, then
      Settings > Accessibility > The Collar > On. This is now **load-bearing**:
      ShadeGuardService is the full foreground-app watchdog that enforces the
      cage at COLLAR+, not just a shade-collapse.
- [ ] If you enable any accessibility service via adb: **APPEND, never overwrite**
      — a bare `put` wiped the wearer's list once already and there is no recovery.
- [ ] **Before the partner's real Lion pairs**, clear the throwaway test-Lion key:
      `adb -s R5CT339K1ZL shell settings delete global focus_lock_lion_pubkey`.
      Otherwise they hit "already paired with a different Lion", which has no
      in-app recovery — only Release Forever or factory reset.
